## 1. 把和谈补上

**用户**：把和谈补上

**助手**：

战争只能回答"谁在推进"，回答不了"什么时候停"。以前只有一种结局：打到对方全灭。

### 战争分数

```
分数 = 我占了他开战国土的百分比 − 他占了我开战国土的百分比
      （按区域价值 vp 加权，双方互为相反数）
```

地图上被占领的省，谁的旗子就是谁的——地是打下来的，谈判不能凭空变出来。

### 条款

| 条款 | 价值 | 付方 | 收方 |
| --- | --- | --- | --- |
| 政治羞辱 | 10 | 稳定度 −10、战争支持 −12 | 政治点数 +20、战争支持 +6 |
| 战争赔款 | 15 | 工厂 −2、政治点数 −25 | 工厂 +2、政治点数 +25 |
| 解除武装 | 20 | 师数 −35% | 边境压力减轻 |

领土两项：**保持占领现状** / **恢复战前边界**（后者对赢家是纯让步）。

### 对方为什么会签

```
赢家：接受线 = 分数 × 胃口(1.25 − 厌战)     ← 我们在赢，血不能白流
输家：接受线 = 分数 × 容忍(1.35 + 厌战)     ← 再打下去只会更糟，赶紧止损
```

两个系数都刻意大于 1：赢家会多要"血债"，输家愿意付出比已经丢掉的更多来止血，
**这个差值就是你能索要的空间**。

被拒的代价是政治点数 −10，对方厌战 +0.04——于是有了一条能磨的循环：
打 → 分数涨 → 提条件 → 被拒 → 对方更软 → 再谈。

### 顺带改的三处

1. **战争有了代价**：每多一个交战对手，政治点数产出 `×(1 − 0.12×敌人)`。
   没有这条，赢家没有理由上谈判桌，谈判桌就只是给输家用的逃命票。
2. **停战协议 540 天**（`state.truces`）。
3. **战争档案**（`state.wars`）：每场仗存开战时的边界快照。存档升到 v4，
   v3 老存档读进来时以当前边界补基准、分数从 0 重算。

### 浏览器里抓到的三个问题

1. 弹窗底部按钮被截断（`.modal` 整块滚动）→ 改成头尾固定、只有正文滚动。
2. AI 国家卡片上把分数标成「我方/对方」→ 改成国名（卡片可能是 AI 国家的）。
3. 条款文案「法兰西共和国 付方稳定度 -10」→ 去掉「付方/收方」。

新增 19 条测试（合计 101）。

## 2. 视觉规范评价与落地

**用户**：给出一份完整的视觉规范（档案馆 / 内阁会议室 / 旧地图；深墨绿灰底、米灰纸面、
铜金或暗红强调；节点四态 locked/available/completed/selected；可访问性要求），
末尾问「你觉得这么设计如何？先评价再落地」。

**助手**：

先说评价——规范整体对，但有七处会在实现时出问题：

**1. 「主强调色：暗红或铜金」二选一是个隐患。**
选中态、已完成印章、宣战按钮抢同一个色相。必须分工：
**铜金 = 可交互（选中 / 主按钮 / 可用节点），暗红 = 既成事实与不可逆（已完成 / 宣战）。**

**2. 「locked：低对比」会把树做塌。**
锁着的节点占全树约七成。面积最大的元素对比度最低，远看就像加载失败。
改成"降饱和 + 虚线 + 锁形图标"，**文字仍保持 4.5:1 以上**。

**3. 「不要脏旧滤镜」和「墨迹/噪点」是同一根轴的两端，需要数值预算。**
页面噪点 ≤5.5% alpha、纸面 ≤7%，只做背景层，**永不用运行时 SVG filter**——
画布每帧重绘，实时滤镜会掉帧。

**4. 「可缩放拖拽」和「焦点环」会互相冲突。**
节点是 HTML 按钮，放在 `scale()` 的容器里，焦点环会跟着放大变粗。
解法：`outline: calc(2px / var(--zoom))`。

**5. 1024 的降级策略规范里没写。**
详情变抽屉、导航收窄、顶栏标签变小——但**不砍功能**（小屏不等于功能缺失）。

**6. 字体不能依赖网络。** 系统衬线兜底链；**状态栏数字必须等宽**，否则 99→100 整行跳动。

**7. 纸面在深色界面里是屏幕上最亮的东西。** 这不是缺陷，是层级信号——
前提是纸面节点数量要少。

**执行判断**：不做单文件 demo。项目里已有可玩代码，只有真实的内容密度
（20 个节点、六个国家精神、和谈桌）才能验证这套规范站不站得住。

### 落地

三层自我约束写进了 CSS 头部注释：

1. 纸面是**局部材质**，不是全局底色（承载面是 `#101615` 深墨绿灰）。
2. 纹理只做背景层，烘成 data-URI 的 SVG，不用运行时滤镜。
3. 强调色分工（铜金 / 暗红）。

节点四态的形状语言：

| 状态 | 线索 |
| --- | --- |
| locked | 虚线边框 + 锁形图标 + 降饱和 |
| available | 米灰纸面 + 铜线边框 + 左上角 L 形角标 |
| current | 纸面 + 铜线 + 底部暗红进度条 |
| completed | 发暗的纸面 + 右上角倾斜的**暗红印章** |
| selected | 实线铜环；键盘焦点是**虚线**铜环 |

**色板是算过的**，不是"看着还行"。脚本 `tools/contrast-check.mjs`：

```
正文 #cdd5d0 on #101615 ....... 12.22 : 1   AAA
次要 #93a09a on #101615 .......  6.74 : 1   AA
弱化 #7e8a84 on #151d1c .......  4.78 : 1   AA
纸上 #2b2823 on #d6d0c0 .......  9.54 : 1   AAA
```

第一次跑 `textFaint` 和 `paperDim` 都不够（4.41 / 4.46），调了两个色阶才齐。

### 三个实现里的坑

1. 弹窗底部按钮够不到 → 头尾固定、正文滚动。
2. `fit()` 用 `offsetWidth` 测内容尺寸，在详情面板刚收起那一帧读到旧值 → 改成
   `getBoundingClientRect()` 除以当前缩放。
3. 未完成节点的「20 天」标签会卡住（只在 current 更新）→ 状态切换时统一重置。

六块区域（顶栏 / 左侧索引导航 / 画布 / 详情 / 档案 / 日志）全部落地，
政治·经济·外交·军事共用一个档案渲染器。

## 3. 国境线与大陆级地图

**用户**：做个国境线吧，地图效果太差了（如果可以就扩大模组地图，至少整个洲）

**助手**：

### 国境线是算出来的，不是画的

相邻两省在多边形里共享同一条边。渲染时比这条边两边归属，不同就画深色线。
**打下柏林之后，国境线自己会挪过去**——它反映状态，不是数据。

```
省份多边形 = 海岸线 ∩ Voronoi(省会种子点)
国境线     = 相邻省份共享边中，归属不同的那一段
```

### 地图是生成的

手画 40 个省的多边形不现实，手画一条海岸线是现实的。

```
tools/map-spec-*.mjs     手写：海岸线 + 省会种子点
        ↓
tools/build-map.mjs      Voronoi 划分 → 用陆地多边形裁切
        ↓
data/**/map.json         省界多边形 + 算出来的邻接表
```

**邻接表也不是手写的**：共享两个以上顶点就算接壤。海峡两岸（日本↔朝鲜、台湾↔福建、
海南↔广东）几何上推不出来，spec 里手动补。

### 东亚扩到整个洲

10 个省 → **42 个省**：中国本部 24 省、满洲三省、蒙古、新疆西藏青海、朝鲜、日本四岛、
台湾海南、法属印度支那四块。欧洲图 28 个省，加了联合王国/意大利/波兰/西班牙/瑞典/南斯拉夫。

### 三个坑

1. 小浮层根本看不清地图（国境线 0.2px）→ 加「图」按钮，大地图弹窗。
2. 手画的希腊把伯罗奔尼撒折成了 X——多边形自相交，裁剪算法不报错但静默算错，
   面积还是"对"的（重叠和空洞互相抵消），屏幕上只是冒出几块大三角。
   → 生成器加自相交检测，直接抛错指到具体哪两段。
3. 意大利的靴子往返穿过两次，射线法把罗马算成了海 → 意大利拆成独立的陆地多边形。

**最有用的工具是 `tools/plot-map.mjs`**：在终端打一张 96×40 的 ASCII 图。
手写海岸线出错时浏览器里只表现为"几块奇怪的形状"，在终端画字符图十秒就能定位。

## 4. 国策点不上

**用户**：国策点不上

**助手**：

是我上一轮加画布拖拽时引进的。

```js
function onPointerDown(e) {
  viewport.setPointerCapture(e.pointerId);   // ← 就是这一行
}
```

一旦 `setPointerCapture` 被调用，后续的 `pointerup` 和紧随其后的 `click` 都会被
**重定向到 viewport**，指针下面那个 `.focus` 按钮的 `onclick` 永远收不到。
所以现象是：能拖能缩放，就是点不动，也不报错——点击确实发生了，只是送错了人。

地图能点，是因为 `.situation` 面板是 viewport 的兄弟节点，不在捕获范围里。

**修法**：只在确认"这是拖动"之后才捕获——按下时只记起点，移动超过 4px 才
`setPointerCapture`。没有移动的按下-抬起，一路都不捕获，click 正常落到按钮上。

这个项目栽在"点击丢失"上有三次了（面板 180ms 重建吞掉 mousedown/mouseup、
档案页重建、指针捕获），都是同一类问题：**中间隔了一层会重新派发事件的东西**。

## 5. 图太粗糙了

**用户**：图太粗糙了

**助手**：

粗糙是三个具体原因。

### 一、海岸线是折线

加了 **Chaikin 角切割**（两轮）：每个顶点按 1/4 和 3/4 切角。40 个点变成 160 个，折线变曲线。
**只平滑海岸，不平滑省界**——省界本来就是直的，那是 Voronoi 的特征。

### 二、省份大小失控

这是最伤的一处。直接拿手放的种子做 Voronoi，面积能差几十倍：西伯利亚一格盖过整个法国，
低地国家挤成几条缝。加 **Lloyd 松弛**：反复把种子挪到自己单元的形心，5 轮之后格子自然等大。

```
europe    28 个省　面积 最小 0.25× 中位 7601 最大 2.87×
eastasia  42 个省　面积 最小 0.06× 中位 9832 最大 2.14×
```

松弛之前这个数是 10× 以上。生成器现在直接打离散度。

### 三、画法没有层次

按地图集的规矩分层：

```
陆地（带投影）→ 省份填色 → 省界 0.5px
→ 海岸线 1.15px 浅色墨线（画在省份之上）→ 国境线 1.9px 深色
→ 斜纹（争夺中）→ 标签
```

再加：陆地 `drop-shadow` 从海里托起来；省名**碰撞剔除**（大的省先占位，挤不下就不画）；
国家名改成 opacity 0.3 的水印。

### 顺带修的

- 上缘的直切线露在画面里 → 切到 viewBox 之外。
- 东南那一刀像尺子画的 → 改成 10 点的弧再过 Chaikin。
- 大地图加 try/catch（调试时被静默异常坑过一次）。

### 还差的

岛还是糙（台湾是根细条，海南是个小点）；省份精度不够；**没有地形**。

下一步顺序：岛屿单独处理 → 省份加密 → 加地形（山脉/河流）。
